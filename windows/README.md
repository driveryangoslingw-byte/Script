# Bosch BES2 Windows: подтверждённое чтение Intuvia

23.10.2026 на физическом Intuvia `108C:0155` получен ответ `62 02 20 05 09 02 00`: **версия ПО 5.9.2.0**. Исправлены начальный sequence SWA и смещение CAN-записи. [Техническое исследование](BES2-TRANSPORT-FINDINGS.md).

Запустите **BoschBES2Auto.exe** и нажмите **ЗАПУСТИТЬ АВТОМАТИЧЕСКУЮ ДИАГНОСТИКУ**. Программа проверит USB, согласует режим, выполнит одно чтение BUI и сохранит JSON в `reports/` рядом с EXE. Одна кнопка выполняет один сеанс; после ответа поток закрывается. Для следующих исследований BUI можно выбрать ограниченный read-only DID на вкладке «Исследование и сравнение». Python и отдельно установленный .NET для самостоятельного EXE не требуются.

В интерфейсе есть остановка, HEX/API-лог, уровни USB/транспорт/сессия/ECU, выбор задержки 0–3000 мс и сравнение JSON. Запись параметров, сбросы, SecurityAccess, команды движения и перебор адресов отсутствуют. Текущий подтверждённый объём — версия ПО BUI; двигатель и батарея пока не проверяются.

## Новые read-only тесты BUI (после успешного 0220)

**Общий пробег `0249` подтверждён сопоставлением USB и показания дисплея**: `00 23 80 5E` → unsigned big-endian `2326622` м → `2326.622` км → **`2326.6 km`** на Intuvia. Это измерение относится к данному велосипеду; другие версии устройства ещё не проверены. Программа интерпретирует только ровно 4 байта при совпавшем положительном ответе CAN/UDS. Сохраняет исходный HEX и выводит километры с одним знаком после запятой. Данные проверены одним сравнением на физическом велосипеде, а не длительным статистическим испытанием.

В программе открой вкладку **«Исследование и сравнение»** и выбери параметр BUI (DID). Доступны: `0220` (версия ПО; подтверждено на велосипеде), `0221` (аппаратная версия), `0222` (дата изготовления), `0249` (**общий пробег, подтверждённый сравнением с Intuvia**), `024A` (язык), `024B` (единицы), `024C` (дневная яркость), `0250` (ночная яркость), `0251` (контраст). Названия других DID взяты из справочного каталога; **их доступность и смысл ответа на данном Intuvia не подтверждены**.

Каждое нажатие **«ЗАПУСТИТЬ АВТОМАТИЧЕСКУЮ ДИАГНОСТИКУ»** выполняет **один** USB-handshake и **один** read-only `UDS 22` к выбранному BUI DID, затем останавливается. Нет автоматического списка запросов, перебора CID, DU/BMS-профилей или повторов после ошибок. После результата закрывается USB handle.

Для DID `0220` и `0249` программа умеет сохранять подтверждённые значения версии ПО и пробега; для остальных DID программа может сохранить `BUI_READ_CANDIDATE_UNVERIFIED` с сырыми байтами, но **не декодирует величины, не угадывает единицы и не увеличивает verified_ecu_values**. Известное чтение `0220` интерпретируется как версия Intuvia, а `0249` как пробег в километрах (метры, big-endian uint32, деление на 1000). Убедись, что проверяешь именно неподвижный велосипед с включённым Intuvia.

Ошибки `00 FF`, неизвестные кадры, чужой CID и неправильный DID не трактуются как положительный результат. В `reports/` сохраняется JSON со всеми 65/64-байтовыми исходными сообщениями и параметром `research_did`.

## Командная строка

```
BoschBES2Auto.exe --enumerate --report-dir C:\Reports
BoschBES2Auto.exe --probe --delay-ms 0 --report-dir C:\Reports
```

`--enumerate` не открывает поток и не пишет в устройство. `--probe` отправляет handshake и не более одного известного запроса чтения. Коды выхода: 0 — перечисление/подтверждённое чтение; 2 — неверные аргументы; 3 — чтение не подтверждено; 4 — ошибка сохранения; 130 — отмена.

Это GUI EXE: для автоматизации из PowerShell используйте `Start-Process -Wait -PassThru` с перенаправлением stdout/stderr. Именно этот способ проверен на готовом самостоятельном EXE; отображение Console.WriteLine и Ctrl+C в обычной интерактивной консоли не гарантируется. В интерфейсе отмена доступна кнопкой СТОП.

## Сборка и тесты

```
dotnet run --project windows/BoschBES2.Tests -c Release
dotnet run --project windows/BoschDiagnostic.Tests -c Release
dotnet run --project windows/BoschSniffer.Tests -c Release
dotnet publish windows/BoschBES2Auto -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:PublishTrimmed=false -o windows-dist
```

Workflow **Bosch BES2 Windows EXE** собирает оба EXE и запускает три набора тестов. Артефакт: **Bosch-BES2-Windows-USBPcap-Sniffer**. Сниффер требует отдельно установленный USBPcap; тестирование реального захвата в этом исследовании не выполнено, поскольку драйвер не установлен.

Полные отчёты могут содержать идентификаторы и остаток USB-буфера. Программа сохраняет их локально; перед публикацией нужна проверка. Публичные тестовые фикстуры очищены от хвоста реальной памяти.
